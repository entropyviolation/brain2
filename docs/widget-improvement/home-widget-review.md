## b. Layout, UI, design, and style

### Overview

The square already has the right furniture: amber caption pip (`is-review`), CRT numeral, equal-height tile, Open / Dismiss keys, footer. The face is telling the wrong sentence.

- Put the next rite in the CRT, not the raw total. Tonight that readout is `Morning`, with the footer `in progress · bed`. A second quiet line can hold the split that the data actually has: `2 today · 8 older` (morning partial, tonight’s night, Thursday’s missing night, and the seven empty longer slots). The catalog footer “Daily” is the shape; `Friday, October 9` repeats the date plate and hides Morning vs Night.
- One door. The face and the Open key should do the same thing: resume the first undone slot (tonight, the telegram morning at `bed`). Dismiss stays the session hide it already is, visually the lesser key — the 10px keys under the CRT are padded `1px 3px` and read as a second instrument. Keep them in the tile’s button bay, same height, and let the amber pip mean “one is already started.” A clear day can show CRT `0` and stay in the strip; `return null` pulls the square out of the row, and with this backlog that empty state never arrives anyway.
- Do not paint a second glyph language. Sun and moon already name day rites in the header menu; a single pip state is enough on a 200px square (steady green when the next slot is `none`, amber when it is `partial`).

### Detail view

The dialog is a silver handheld with a power lamp and LCD rows, then it wastes that chrome. Each row is `title · period` plus the strings `app Header → Rituals → …` and `text gm` / `text gn` / `text review week`. Those are operator paths, in `text-muted-foreground`, on a `#07140f` well.

- Top of the scroll: three wells in the existing `WidgetWells` grid. **Next** `Morning`, **State** `in progress`, **Due** `10`. The power lamp on the caption goes amber while any row is partial (the hide confirm already has `home-widget-power is-amber`).
- Group the rows the way the slots already fall, with a 9px uppercase label per group: **Today** (Morning partial, Night not yet), **Last night** (Thursday, October 8, not yet), **Longer** (the seven empty period slots, each named `Start` or `Review` plus the period title the code already builds: `Week of Sep 28`, `October 2026`, `September 2026`, `Quarter 2026 Q4 (Winter)`, `Quarter 2026 Q3 (Fall)`, `2026`, `2025`). One dim row for the week start that is done, so the 10 is auditable: `Week of Oct 5 · start done`.
- Row copy is status and resume, not a command. Morning’s row reads `Morning · Friday, October 9` and `in progress · bed`. Night rows read `not yet`. Drop the telegram verb and the header path from the LCD. The Open key on a row is the same metal key it is now (`is-on`), and it should open that slot’s walk, then close. It should not click the header menu.
- A fourth small group, **Left open**, for the four partials the window dropped (Sept 26 morning, Sept 27 morning, Oct 4 night, Oct 5 night), each with its resume or `end not saved`. They are in the store and absent from the square.
