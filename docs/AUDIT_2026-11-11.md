# Brain2 audit — 2026-11-11

How this was made: I read the root, `lib/`, `components/` and room READMEs, the configs, `electron/`, the dev server and its `scripts/*-api.mjs` handlers, and the persistence layer (`lib/vault-guard.js`, `lib/phone-window.ts`, `scripts/persist-api.mjs`). I ran `tsc`, `npm audit` and `vitest`, took code-health counts across all 2,385 non-test source files, and looked at the screenshots in `docs/screenshots/` (from 2026-10-24). I did not open the running app. A fresh browser profile pointed at the live persist hub is how past wipes started.

Size: about 514k lines of non-test TS/TSX/JS app code (760k once the 150k lines of tests and the scripts are counted), plus 108k lines of CSS in 155 files, 69k lines of Markdown in 332 files, 1,118 test files, 79 persisted Zustand stores and 666 commits.

## 1. What is wrong, room by room

### Repo and build hygiene
- **CI is red on `main`.** `npx tsc --noEmit` fails with 2 errors in `lib/instagram-account-merge.test.ts` (lines 45 and 65, TS2352: test fixtures cast to `Task` while missing `description`, `stage` and `lists`). CI runs `tsc` before tests and build, so nothing after it runs.
- **Vitest also picks up `.claude/worktrees/**`.** That folder is 17 GB across 5 worktrees. `vitest.config.ts` excludes only `node_modules`, `e2e` and `.mobile-build`. So `npm test` runs every worktree's copy of the suite (it never finished: my 20-minute limit stopped it, with no summary printed) and fills the log with "Invalid hook call" errors from duplicate React copies.
- **Junk in the working tree:** `homedesignref.zip` plus its unpacked folder, `plyvel-1.5.1.tar.gz`, `knowledge-graphs-course.html`, a copyrighted O'Reilly PDF in `docs/`, `tsconfig.tsbuildinfo`, `scripts/face-photos/__pycache__/`, and untracked `scripts/zz-*.mts` files. Reference image folders sit at the repo root and in git: `animalsrcs`, `clockbgssrc`, `cosmeticsandperfume`, `designrefs`, `naturerefs`, `litrefs`, `gems`, `folders` (about 400 files).
- **7 orphaned `data/shared-persist.json.*.tmp` files.** Atomic writes were interrupted and never cleaned up.
- **Dependencies pinned to `latest`:** `@radix-ui/react-checkbox`, `react-collapsible`, `react-label`, `date-fns` and `recharts`. Builds aren't reproducible when the lockfile moves.
- **`npm audit --omit=dev`:** critical for `next@15.2.4` and `@capacitor/ios@7.6.8`; high for `xlsx` (no npm fix exists), `lodash`, `postcss`, `sharp`, `glob`/`minimatch`/`picomatch` and `nanoid`.
- **Lint is effectively off.** `.eslintrc.json` is only `next/core-web-vitals`, `next.config.mjs` sets `ignoreDuringBuilds: true`, and CI doesn't lint. There are 104 `eslint-disable` comments, 81 of them for `react-hooks/exhaustive-deps`.
- **Two server languages.** `scripts/*.mjs` and `electron/*.js` are plain JS with no type checking (about 26k lines, including the persist hub, the most dangerous code in the repo). Only `lib/` and `components/` get `tsc`.
- **`tsconfig` target is `ES6`**, which is old for an Electron, iOS 16+ and modern-browser app.

### Persistence and sync (the biggest problem)
- **The source of truth is several copies that heuristics keep in line.** Data lives in browser `localStorage` (about 5 MB origin quota), Electron's own profile, a hub JSON file (`data/shared-persist.json`), two SQLite shadows (`*.rows.sqlite`, `*.vaults.sqlite`), a phone "window" in memory with an outbox, and launch caches. Merges are decided by `lib/vault-guard.js` (2,611 lines) using shrink guards ("reject a write below half"), `appearanceRev`, `contentRev`, tombstones, `restoredTaskIds` hints, union-by-id, "20+ items back in Inbox means stale", `tombstonesReplayMass` and `rowsMissingMass`.
- **It has already lost data repeatedly, per its own docs.** 2026-09-21: an empty profile with 15 items against 2,455. 2026-10-30: a phone patch removed 881 lists, 739 items and 25 habits. Same day: 45 `habit-done-*` rows were removed. Each fix added another heuristic. Heuristics can't make merging correct. Only a model with one owner, versioned rows and real conflict rules can.
- **The vault is about 16 MB, but the browser store has about 5 MB.** It works only because of IndexedDB side stores, gzip, row cursors and key aliasing (`cogs-*` and `brain2-*` dual writes).
- **79 persisted stores, each with its own version and migrations.** `task-store` is at v19 and `habits-store` at v26. There is no single schema version, and each store rehydrates at boot independently.
- **Whole-blob writes.** Zustand `persist` serializes a store's entire state on change, so one checkbox rewrites megabytes and races other windows.
- **Date fields have flipped meaning before.** Persist v17 moved dates off UTC midnight. Local-versus-UTC keys appear throughout (`formatDateKey` legacy UTC in `regret-store`, tests pinned to `America/Los_Angeles`).

### Security
- **The vault API is open to the whole network.** `scripts/cogs-dev-server.mjs` and `cogs-prod-server.mjs` bind `0.0.0.0`. In `scripts/persist-api.mjs`, `GET`/`PUT`/`POST /api/persist`, `/api/persist/rows` and `/api/recovery-backups` have **no token check**. Only the model proxy checks `BRAIN2_PHONE_HUB_TOKEN`, and it is "open when no hub token is set". `guardBrowserOrigin` stops other websites in a browser, but any device on the Wi-Fi (or Tailscale) can `curl` the whole life vault or overwrite it. It also trusts *any* private-IP origin, such as a router page or another LAN dev server.
- **The model proxy has no auth by default,** so anyone on the network can spend your model credits.
- **`/api/sync` defaults to `admin`/`admin`** (`scripts/sync-api.mjs:20-21`) and compares with plain `===`, which isn't constant-time.
- **`/api/ingest/*`, `/api/code-docs/*` and `/api/baby-gens` don't check the caller's address.** Ingest can enqueue writes, and code-docs serves repo files with `Access-Control-Allow-Origin: *`.
- **`scripts/capture-box.mjs` and `mobile-sync-server.mjs` also default to `0.0.0.0`.**
- **Unsanitized HTML:** `components/Docs/DocsHome.tsx:129` renders stored Doc HTML raw, and also cuts it at 4,000 characters, which can split a tag. The other raw-HTML sites go through sanitizers (`markdown.ts`, `sanitizeWiktionaryHtml`); verify each one.
- **`NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is compiled into the static bundle** (`lib/transit-time.ts`), which ships inside the Electron and iOS apps.
- **Next 15.2.4 has critical advisories,** and the dev server running it is exposed to the network.
- Good already: Electron windows use `contextIsolation`, `sandbox`, `webSecurity`, a navigation guard and a window-open handler, and Instagram sessions are sealed with `safeStorage`.

## 2. How the codebase could be improved, in detail

### 2.1 Replace "many copies and heuristics" with one owner and a log
1. **Pick one authoritative store:** SQLite on the Mac (you already have `*.rows.sqlite`), reached through one typed API. Every client (Electron renderer, Chrome tab, phone) is a cache of it.
2. **Store rows, not blobs.** Each record gets `id`, `kind`, `version` (or a hybrid logical clock), `updatedAt`, `deletedAt` and `deviceId`. A write is "upsert row N at version V". Conflicts resolve per field (last writer wins per field, or explicit merge rules for lists and logs), not per store.
3. **Use a mutation log or outbox on every client.** Clients send *operations* (`completeHabit(id, day)`, `moveTask(id, list)`), not snapshots. The server applies them in order, and clients pull a change feed by cursor. That removes the shrink guard, `contentRev` and `appearanceRev`, tombstone replay mass and the "20 back in Inbox" rule. An empty client can no longer wipe anything, because "send me my whole state" stops being a write.
4. **Consider a sync engine rather than building one:** Replicache or Zero, ElectricSQL, PowerSync, Automerge or Yjs for docs, or simply `cr-sqlite`. Any of them gives this model off the shelf.
5. **Migrate in steps.** First put the hub behind the row API and make every writer go through `dispatchItemMutation` (you already started the one-write-door rule). Then move one store at a time (points, then habits, then tasks) from Zustand `persist` to "Zustand as a view over the synced rows". Keep `vault-guard.js` as a read-only alarm until the last store moves, then delete it.
6. **One schema version and one migration runner** (for example SQL migrations), not 79 `persist` versions.
7. **Keep bytes out of the state model:** attachments, Docs HTML and images go in the server's blob store, addressed by hash.

### 2.2 Lock down the network surface
- **Bind to `127.0.0.1` by default.** Expose to the LAN or Tailscale only when a flag is set and a token exists.
- **Require a bearer token on every `/api/*` route,** including persist, rows, recovery, ingest, code-docs and the model proxy. Compare with `crypto.timingSafeEqual`. Generate the token on first run and pair the phone with a QR code.
- **Remove the `admin`/`admin` default,** and refuse to start sync without credentials.
- **Narrow the origin trust** from "any private IP" to a specific allowlist.
- **Upgrade `next` and `@capacitor/ios`, and replace `xlsx`** with SheetJS from its CDN tarball, or with `exceljs`. Pin every `latest`.
- **Sanitize all stored HTML at render time** with DOMPurify, and make thumbnails from text, not cut HTML.

### 2.3 Make the code checkable again
- **Fix the 2 TS errors and add `.claude/**` (plus `**/worktrees/**`) to vitest's `exclude` and tsconfig's `exclude`.** CI goes green and the suite drops back to about one sixth of its current run.
- **Turn on lint in CI** with `typescript-eslint` strict, `react-hooks` as errors, `no-floating-promises` and import cycles. Burn down the 81 `exhaustive-deps` disables; most hide stale-closure bugs or should become `useEvent`/store selectors.
- **Convert `scripts/*-api.mjs`, `electron/*.js` and `lib/*.mjs/cjs` to TypeScript,** or at least `// @ts-check` with JSDoc, and include them in `tsc`. Share request and response types between the hub and the clients (zod schemas once, used on both sides).
- **Split the 87 files over 800 lines.** Pull pure logic out of the big `.tsx` files into `lib/`, where it's already tested, and keep components under about 300 lines.
- **Move the experiments out:** BabyGame, Lab and star catalogs become workspaces (`packages/baby-game`, `packages/lab`) or separate apps loaded on demand. That shortens type-check and test time and keeps the core small.
- **Add a cheap test pyramid:** pure `lib/` unit tests (you have many), property tests for merge and sync, a handful of Playwright journeys (capture → clarify → schedule → complete → see it in Data), and run e2e in CI.

### 2.4 Shrink the styling system
- **108k lines of CSS can't all be live.** Introduce design tokens (color, spacing, type scale, radii and bevels as CSS variables), a dozen chrome primitives (`Bezel`, `Keycap`, `CRTReadout`, `GroupBox`, `Plate`) and Tailwind or CSS modules for layout. Then delete per-room copies. Use a coverage pass (Chrome DevTools coverage or PurgeCSS report) to find dead selectors.
- **Remove the 730 inline `style={{…}}` objects,** or route them to tokens.

### 2.5 Domain model
- **`lib/types.ts` (2,643 lines) is a god type.** Split `Task` into a small core `Item` (id, title, body, type, timestamps) plus typed facets (`Schedule`, `Habit`, `Person`, `Operation`, `Book`, …) stored as related rows. "Installable modules" then add facets, not fields.
- **One `Person` model** used by People, Friend, Instagram, Social BIMBY and `personProfile`.
- **One `Step`/`Subtask` tree component and model** (To Do lid, ItemDetail, Operations).
- **One calendar engine** feeding both Plan and Scheduler.
- **One scoring engine** (points, regret, grades and bonuses as plugins of one ledger) with a "why this number" explanation for each.

### 2.6 Docs
- **Keep READMEs short and current:** what it is, entry points, invariants, a file table with one line per file. Move "Before, …" history into commit messages or a `CHANGELOG`. Cap table cells at about 200 characters (`docs:check` can enforce it).
- **Archive finished or dead plans** into `old_plans/`, and remove copyrighted PDFs and course HTML from the repo.

## 3. Top 5 design improvements (style and interaction)

1. **A type and contrast floor.** Nothing under 11 px, no grey-on-grey under 4.5:1. The nav labels, row metadata ("Task U4 I4") and sidebar copy in the screenshots fall below both. Keep the Win95/chrome/CRT language, but make the readable layer modern-legible.
2. **One focal point per screen.** Each room gets a single primary panel and a quiet periphery. On Home, make "what's next" the hero, and let the dashboard, LED sheet, gems, moon and points collapse into a secondary rail or a "Data" drawer. Today every element shouts at the same volume.
3. **A smaller, tokenized chrome kit.** Build about 12 shared primitives so every room's bevels, CRT readouts and keycaps are identical, then delete the per-room CSS forks. That gives consistency for free and makes theme switches (warmth, PCB plate) one-variable changes.
4. **Calm the backdrop.** The PCB/"OKAK" texture behind content competes with the panels. Dim it or blur it under windows, and keep the surreal orb and velvet richness inside content, as `DESIGN_STYLE.md` intends, not behind it.
5. **Motion and feedback with meaning.** Give consistent press, commit and undo feedback: the keycap drop, a toast with Undo on every destructive or cross-store write, and visible sync state ("saved on Mac ✓ / queued on phone ⟳"). The data-loss history shows that users need to *see* where their data is.

## 4. Top 5 UX improvements (flow and features)

1. **One capture door, one triage loop.** Keep a single global capture (hotkey, phone share, Telegram all land in the same Inbox) and one daily "clarify" flow that files each line (BIM Chat's proposal card is the right shape). Retire the parallel Now / Quick Add / shorthand paths, or turn them into modes of the same box.
2. **Real global search and command palette.** Cmd-K across items, docs, people, lists, tracking, texts and settings, with actions ("track 30m reading", "move to Tomorrow"). This is the missing half of "capture once, use everywhere", and the room is currently 509 lines.
3. **Merge overlapping rooms.** Combine Plan and Scheduler into one Calendar, fold Operations' To Do into the shared task tree, and keep one Person page. Cut the top-level tabs from ten to about five: Today, Lists, Calendar, Data, Library (Docs, Modules, Inventory). Move BabyGame, Lab and Agents behind a "Play / Lab" door.
4. **Make "Today" answer one question: what do I do now?** One ranked next action (you already have `startOrderFor` / `rankStartSteps`), the current clock, and today's plan versus what happened. Scores, grades and gems live one click away. Add a first-run or empty state, because a new profile currently shows a dense dashboard with no guidance.
5. **Trustworthy phone.** Make the phone usable offline (local cache plus an op log, per §2.1), show sync status, and pair with a QR token. Today it is a window onto a Mac that must be awake and on the same Wi-Fi.

## 5. Top 5 code improvements (efficiency, safety, room to grow)

1. **Replace snapshot merging with a row-and-operation sync model** around one SQLite owner (§2.1). This one change removes the main data-loss risk, the 5 MB quota limit, the 16 MB phone download, `vault-guard.js` and most persist migrations.
2. **Close the network holes:** loopback by default, a mandatory token on every `/api/*`, no `admin`/`admin`, timing-safe compares, a narrow origin allowlist, and upgrades for `next`, `@capacitor/ios` and `xlsx` (§2.2).
3. **A green, fast CI gate:** fix the 2 TS errors, exclude `.claude/worktrees`, add lint with `react-hooks` as errors, type-check the server and Electron JS, run Playwright journeys, and fail on `latest` pins.
4. **Modularize into packages with clear boundaries:** `core` (types, facets, mutations, sync client), `server` (hub API), `app` (rooms), and optional `baby-game` / `lab`, with dependency rules enforced so a room can't import another room's internals. Split the 87 files over 800 lines along the way.
5. **A design-token and component kit, then delete CSS** (§2.4). Target under 25k lines of CSS. Smaller CSS means faster boot, fewer cascade bugs (your `next.config` comment about "CSS reordered and the skin snapped back to unskinned Tailwind" is that problem) and easier new rooms.
