# `components/Home/Habits/` — Habit Tracker

The Home **Habits** sub-tab — the house’s **favorite surface** and most developed UI. Other rooms look here for the **Habits Tab Control Panel**, analog furniture, **Willpower gems**, CRT phosphor, and designrefs skeuomorph ([`docs/DESIGN_STYLE.md` — Look at Habits](../../../docs/DESIGN_STYLE.md#look-at-habits--how-to-extend)). Supports five measurement types (boolean, goal, text, climb) at **daily**, **weekly**, **monthly**, and **season** (`quarterly`) frequencies. A season is a calendar quarter (`lib/seasons.ts`: Q1 Spring, Q2 Summer, Q3 Fall, Q4 Winter). TIME/COUNT are legacy aliases for GOAL.

Climb (incremental) habits are **not** a per-key spreadsheet. They log one number per day, like a goal, with a derived target. Rules live in **`lib/incremental-habits.ts`**.

## Data

Single source of truth: **`lib/habits-store.ts`** (Zustand + persist, live key `brain2-habits-store`, legacy alias `cogs-habits-store`, **version 26**). Persist **v26** adds `weeklyAverageBeatBonus` and `monthlyAverageBeatBonus` (default 5 each): one ledger row when that day’s raw completion is above the prior 7-day average, and one when it is above the prior 30-day average. A missing value migrates to 5. Optional `timeEstimateNA`, `doneTaskPhrase`, and `doneTaskUseText` on a habit do not bump the version: a missing key keeps a stored estimate and the habit name on the Done line. Persist **v25** stamps `WeeklyTask.completionSources` (trust order) on habits that did not have one, and does not rewrite logged cells. Persist **v24** lifts leftover Willpower `stirHop` still at the old default (160) to 480 so a normal plate press hops. Persist **v23** ensures Tracking-coverage and daily-floor linked habits exist on upgraded vaults (no duplicates). Persist **v20** stores the exemption wand. `migrateHabitsState` spreads any recent blob and only fills missing keys (sort, LED tint, day view, loading bar, **Small LEDs**, gems, tube colors, **control panel width** pinned compact, Willpower gems physics). Persist **v19** adds **`contentRev`**: every title, detail, and completion write stamps the vault, and a late rehydrate or an older same-sized snapshot cannot roll those edits back. Persist **v18** resets leftover `willpowerPhysics` knobs to the calm default whirl. A present `percentLedTint` / `gradeTubeColor` / `outputGradeTubeColor` is never replaced with the Home overview defaults (`#7e14ff` / `#508b51` / `#25366a`). Custom hues with `appearanceRev` 0 are stamped to 1 so a seed hydrate cannot roll them back. It never replaces `tasks` or completions with `[]`. Electron `userData` is pinned to `~/Library/Application Support/cogs` so a package rename cannot boot an empty profile. Daily Habits waits on `usePersistHydrated` so a hub fetch cannot flash seed rows (or “No habits yet”) over the vault; Electron returns a rich local snapshot immediately instead of parsing the 2MB persist hub first. A richer hub vault still overlays those local color keys (and `cogs-theme-store` `pcbMode` / `chromeFace` / `colors`) so an older hub JSON cannot reset them. **`appearanceRev`** bumps on each LED / tube hue pick; a late hub rehydrate keeps the live pick. `choosePersistSnapshot` re-reads disk so a color change during the hub wait is not merged from a stale getItem snapshot. Persist **writes** stamp `cogs-habit-led-tint` from the new blob; they do **not** re-apply a stale pin onto that blob (that was resetting Percent LED tint to a previous purple on refresh). The LED swatch stays disabled until the habits vault has hydrated so a native color input cannot POST a seed tint before the snapshot lands.

Each `WeeklyTask` may be **`priorityPinned`** (until unpinned) and/or **`priorityMuted`** (ignore neglect: drops auto-priority). A fully empty prior week (daily) / week / month / season auto-prioritizes the next period and compounds; the count is empty weeks for daily and weekly, empty months for monthly, and empty seasons for season. Today's morning review (`priorityHabitIds`) marks those habits **MORNING RITUAL** and shows `morningRitualPointMultiplier` (default ×5, edited in Habits Settings with the other point rules). **`priorityLog`** is an optional list of refresh lines, oldest first (missing means none; shown newest first; old lines stay). **`priorityRefreshedOn`** is the local calendar day of the last refresh. **`priorityPermanent`** holds the star and the green sheet highlight at 100% until it is turned off, then the fade resumes from that refresh day. Persist stays at 26. Highlight off leaves the name cell uncolored. Highlight on washes a selected habit green at the star's strength and a neglected habit red (brighter as the empty-period count grows; that red does not fade with the star). A habit can be in the morning ritual, neglected, and selected at once: the red neglect wash stays, and the green edge or wash follows the star. **`gem`** is a catalog path or uploaded data URL for that row’s edit jewel. New habits get a **random** stone from the full `public/gems-removebackground/` catalog (114 PNGs). Existing habits with no stored gem get one on persist **v13** (lazy stamp). Type / category no longer pick the row jewel. A user pick or upload still wins and is not re-rolled.

Persist **v20** adds the exemption wand (`exemptionWand`, `habitExemptions`). Periods that end before the habit existed are exempt with no stored flag (`createdAt`, or the `task-{unix ms}` id when older rows never received that field). A wand click writes an override and clears it when the choice matches that automatic rule again. Persist **v19** stamps `contentRev` on habit titles, details, completions, and exemption overrides so a stale snapshot cannot replace them. A hollow live vault (empty completions, or seed `task-*` rows) with a newer stamp still **overlays disk completions** and heals seed tasks so Week grade / Perfect output do not go blank. Gem stamping after rehydrate does **not** bump `contentRev`. **`hideCompletedToday`** persists with the other control-panel rockers (no version bump). **`habitWeekView`**, **`habitMonthView`**, and **`habitSeasonView`** do the same (default false) and do not change `habitWeekWindow` or `habitMonthWindow`. **`missedOpWand`** and **`hideCompletedAndMissed`** do the same: a missing key migrates to `false`. `TaskCompletion.missedOpportunity` is optional on the cell; absence is not marked, and no migration rewrites logged cells. Persist **v18** resets `willpowerPhysics` to the calm default whirl. Persist **v17** pins `habitsControlPanelWidth` back to 196px (seam resize retired). Persist **v16** adds `habitsControlPanelWidth`, `willpowerPhysicsHud`, and `willpowerPhysics`. Persist **v15** adds `habitSmallLeds` (default on). Willpower gems satellites are **derived** — **one copy per daily completion** on the visible week (`lib/willpower-stones.ts`, id `habitId:YYYY-MM-DD`) — no extra collected-id persist, so reload keeps the same stones. Persist **v14** adds `gradeTubeColor` / `outputGradeTubeColor`. Persist **v13** stamps missing `WeeklyTask.gem` values. Persist **v12** adds `habitDayView` and `percentLoadingBar` (default on). Persist **v11** adds `percentLedTint`. Persist **v10** adds `habitSortMode` (old `sortHabitsByPriorityFlag` true → `priority`, false → `default`). Persist **v9** adds `habitGems`. Persist **v8** adds `willpowerImage`. Persist **v7** adds those flags and toggles. Persist **v6** adds the Good-day settings. Persist **v5** adds `outputGradeTolerance`. Persist **v4** adds `gradeTolerance`. Persist v3 migrates old multi-metric climb maps (`currentValues` / `weeklyIncrement`) into one habit per metric and copies logs onto `TaskCompletion.value`. Legacy `weekly-habits-*` localStorage keys are imported once on first load. New habits stamp `WeeklyTask.createdAt`. Version bumps call `migrateHabitsState` so older JSON (v9/v10/v13) still hydrates tasks.

Completing a habit awards **50 points × that day’s completion ratio** (partial goals/climbs count) via `lib/habit-points.ts` / `points-store.upsertPoints`, and writes a `loggedAction` Done row (`lib/habit-done-log.ts`, id `habit-done-{habitId}-{YYYY-MM-DD}`) so it appears in To-Do **Done** (today / this week / this month) and in Analytics task counts. Unchecking removes that row and zeros that habit’s points for the day. **Cmd/Ctrl-Z** reverses a cell you just marked (`lib/action-history.ts`). Each elapsed day can also earn the **accomplishment bonus** if that day’s score (raw, or the 50% priority blend when `goodDaysUsePriority` is on) meets `accomplishmentThreshold` (defaults: ≥80% → +50), **+100** if either Week grade or Perfect output is 75%+ after its curve (and optional priority blend), or **+300** if both grades are. Two further bonuses (Habits **Settings**, default **5** each) pay once when that day’s raw completion — `rawDayCompletionPercent`, not the letter grade — is above the prior 7-day average, and once when it is above the prior 30-day average. Both can apply. Equal or below pays nothing for that rule. Changing the amount rewrites that day’s row; dropping back to or below the average removes it.

The same store is used by **`Lists/daily-habits-list.tsx`** — changes in Home or Lists stay in sync.

## Exemption wand

A period that does not apply is **exempt**: it leaves the requirement. It is not a completion.

| Rule | What it does |
|------|----------------|
| Before the habit existed | A day, week, or month that **ends** before the habit existed is exempt on its own. The day is `createdAt` when it was stored; otherwise the `task-{unix ms}` id from add time. The creation day, the week that contains it, and the month that contains it stay required. A seed id such as `task-1` is not a date, so those rows have no automatic waiver. |
| All-nighter block | On a daily habit, **Lift when a log says** (`logExemptions`). An all-nighter is the morning date. `evening-before` lifts the day that led into that night (bedtime). `morning-of` lifts that morning (wake, dream). `undefined` uses the name preset; `[]` means the preset was cleared. Weekly and monthly ignore it. A wand “require” beats the block. The chart uses the same grey hatch, titled for that night or that morning. Morning Review lists the blocks under the checkbox. |
| Wand | Control-panel wand stays metal. Pressed, it is crossed out and every cell becomes a yes/no lamp for “waived.” On = grey, unavailable. Off = the ordinary dark lamp (required). Clicking back to the automatic rule deletes the override. The crossed wand leaves the mode. |
| On the chart | With the wand off, an exempt cell is a grey hatch (`.habit-exempt`, cell `.is-exempt`). It is not a lit completion and not an empty miss. The heatmap square uses the same grey (`.is-exempt`). |
| Day % | Denominator is the habits still required that day. Three habits, one waived → divide by 2. |
| Row % | Denominator is the periods still required. One waived day in the week → divide by 6, and that day is not a hit. A goal’s target shrinks the same way. A window where nothing is required shows **—**. |
| Grades | A day or period where every habit is exempt is left out of the average (shown as “exempt” on the milled grade sheet). A habit with no required periods in the window is left out of Perfect output. |
| Hide completed | Also hides exempt rows for the focused day / week / month. |
| Still to do | Plan rail, Home day counts, Lists done/total, morning-review habit picks, and friend suggestions treat exempt like unavailable: not remaining, not done. |
| Points and gems | An exempt day pays 0 habit points and does not drop a Willpower gem. Un-waiving restores both from the completion that is still stored. |

## Missed opportunity

A period can be marked **definitely not done**. That is not “I have not logged it,” and it is not an exemption. The period still counts in the denominator. Daily, weekly, monthly, and season grids all take the mark.

| Rule | What it does |
|------|----------------|
| Wand | **Missed op wand** sits under Exemption wand. Same metal key. Pressed, it is crossed out. Turning it on turns the exemption wand off, and the reverse. |
| Click | While the wand is on, an eligible cell toggles `TaskCompletion.missedOpportunity`. A cell that is already complete, and a cell that is exempt, are grey and cannot be marked. |
| Stored | Optional boolean on the completion cell. Absence is not marked. The write does not clear `completed` and does not reuse `habitExemptions`. |
| Rocker off | The sheet looks as it does today. A missed-op cell is an ordinary not-done cell. |
| Hide completed and missed | A `CockpitSwitch`, default off. On, completed cells, missed-op cells, and a goal whose shown value has reached its goal (30/30) paint with the exemption hatch (`.habit-exempt`). An unmet goal stays a normal field. Rows stay. The missed-op wand is unchanged. **Hide Completed Today / This Week / This Month / This Season** still hide completed rows. |
| Math | Grades, percents, heatmap fill, good days, coverage, streaks, willpower gems, and points do not read the flag. `isHabitGoalMet` and `rawDayCompletionPercent` still treat `completed: false` as not done. |

## Connections

Daily yes/no habits can check themselves from a log. The blocks live on the habit form (**Connections**), so another habit can be wired the same way. A hand tick still counts.

| Block | What it watches |
|-------|-----------------|
| Sleep clock | Bedtime on a day is the evening that leads into the next morning’s night. Wake is that morning. The habit is met when the logged end is at or before the threshold. Name preset: bedtime (11pm if the name has no hour), or wake plus “before” (9am if the name has no hour). |
| To-do list | How many items on a named list, inside Next Actions, were completed that day. The preset is **complete 1 to-do list item** → 1 done item on the list named “to do”. That block is the template: change the count or the list name to make the same connection on another habit. |

`undefined` uses the name preset. `null` means it was turned off. `sleepCompleted` and `listCompleted` mark the auto check the way tracked time uses `trackedCompleted`.

## Time estimate

A habit records an *amount* ("4 pages"), but it always consumed time, and that
time is what makes its Done row worth anything to the review or to Analytics. Add/Edit
Habit → **Time estimate** (`WeeklyTask.timeEstimate`) supplies the missing scale:

| Control | Meaning |
|---------|---------|
| Minutes per *unit* | Scales with what was logged. 10 min per page × 4 pages written = 40m — the amount **logged**, not the goal. Goal and Climb habits only. |
| Minutes per completion | A flat length. The only option for Yes/No and Text habits; on a Goal habit it is the fallback when no rate applies. |
| This length is exact, not a guess | `precision: "definite"`. The derived duration is recorded as fact instead of being flagged for confirmation. |
| N/A | `timeEstimateNA`. No minutes are stored. Grades and the plan treat this as no estimate, not as 0 minutes that would still book a block. Unchecking shows the number fields again, with the minutes from this visit. A habit that already has a number stays as it is until you check N/A and save. |

Habits already measured in time (unit `minutes` / `hours`) need no estimate — the
logged value *is* the duration, and it is recorded unflagged. Painted Tracking time
outranks a rate: minutes on the habit's linked tags are observed, and a rate is
only used to top up a hand-logged remainder.

Meeting the goal then writes a Done row carrying the duration **and** a clock
window (`lib/completion-window.ts`): the painted Tracking run when there is one,
otherwise "finished just now" for today, otherwise — for a day already over —
half an hour before that night's bedtime, taken from the sleep log, from sleep
painted on the grid, or from the median bedtime of the last month, and only then
the fixed day anchor (default 9:00 PM). Anything assumed is flagged and shows as
**est.** in Home → To Do → Done, where it can be confirmed or corrected.

## Done task wording

Optional, and closed until you open it on the habit form. The Done line is written by `habitDoneLogLine` in `lib/habit-done-log.ts` when a completion is logged from now on. Rows already on the Done list are not rewritten.

Leave the phrase blank and the line stays the habit name.

`{value}` is the number you actually logged, which can differ from the goal. “read {value} pages” with 7 logged becomes “read 7 pages” even when the goal is 3. A phrase with no `{value}` is used as written. That is the yes/no case: “drank water”.

A text habit can check **Use the text entered**. If the cell says “made jewelery”, the Done line says “made jewelery”. It still counts as that habit; only the displayed wording changes. The link on the Done row stays.

If you log a different number later on a line that already used this phrase, `{value}` follows the new number. A line written before any phrase was set keeps the habit name.

## Auto-fill from Tracking

A daily **Goal** or **Yes/No** habit can carry a `trackingLink` (`lib/types.ts`) that pulls time straight out of Home → **Tracking**. Tag a pen there (e.g. "Do dishes" → *Cleaning*), link the tag here, and every minute painted with any pen carrying it lands on the habit for that day. Weekly and monthly Goal / Yes/No habits use the same control: tagged minutes are **summed across the week or calendar month** and written to `weeklyHabitData` / `monthlyHabitData`.

The tags and **Create tag** controls are on screen only while the **Tracking tags** pipeline is on. Hiding that row does not delete the saved tags; adding the pipeline again shows them. BIM Keywords and the other pipelines stay their own rows.

Set it in Add/Edit Habit → **Auto-fill from Tracking**:

| Control | Meaning |
|---------|---------|
| Tag chips | Any pen carrying one of the selected tags counts. Slots are unioned across scopes, so a minute tagged in two scopes counts once. |
| Count tracked time as | `minutes` (default) or `hours` (2 decimals), matched to the habit's unit. |
| Combine with manual entries | **Add** (default) tops up what you typed, **Higher of the two**, or **Tracking only**. |
| Minutes needed to check it off | Yes/No habits only — threshold before the box ticks itself. Blank = any tracked time. |
| Auto-fill is on | Suspends the link without losing the tag selection. |

Below the chips the form reports how many pens currently feed the habit, so an unused tag is obvious before saving. **New tag** creates a real Tracking tag (`useTimeTrackingStore.addTag`) and turns it on for this habit in the same step. The tag then exists on Tracking pens, not only as a string on the habit.

**How the value is stored.** The completion keeps the two halves apart — `manualValue` (typed) and `trackedValue` (from the grid) — and `value` stays their combination, so grade math, points, week % and the Done log need no special case. That split makes the sync idempotent: repainting recomputes instead of accumulating, erasing time withdraws it, and typing a number into a linked cell is read as the new **total** (the manual half is back-solved). Completions written before a link existed are treated as fully manual, so linking never erases logged history.

Auto-filled cells are marked in the grid with a clock glyph and a blue border; hovering shows the split (`60 minutes from Tracking + 10 logged by hand`). Yes/No boxes ticked by the tracker get a blue ring, and only those are un-ticked when the time goes away — a hand-ticked day stays ticked.

An Operation can carry the same tags (Settings → Tracking & habits). Time spent **Working on this now** is painted onto the Activity grid with those tags, so this auto-fill runs without a second wiring. See `components/Operations/README.md`.

Climb and Text habits are out of scope (`supportsTrackingLink`); their targets are derived rather than accumulated. Modules: `lib/tracked-time.ts` → `lib/habit-tracking.ts` → `lib/habit-tracking-sync.ts`.

## Tags

A different pipeline from the minute link above. **Add source** → **Tags**, then name one tag (the Tracking tag chips, or a short tag such as `cooking`). The habit’s existing goal is the count. Two Done tasks tagged cooking in the week meet “cook at least 2 times.” One does not. A third task next week stays in that week. A day that has not happened yet is left out. An empty period is 0, and that 0 is not a number you typed. A tracked activity with the same tag files one Done line for that block (`tagged-task-{entryId}` in `lib/habit-tagged-count.ts`) and counts once; logging the block again does not add another. That same tag is also written on this habit’s own Done line. The minute **Tracking tags** pipeline is unchanged and still sums painted minutes; if both are on, they stay two rows. Done-task wording still names the habit’s own Done line; the count reads the tag, not the phrase. The field is on the Tags row. Missing `taggedTaskTag` means the source is off. The stored id stays `taggedTasks`. Persist stays at 26.

### Climb cadences (`incrementalData.cadence`)

Configured in Add/Edit → **Climb**. One metric per habit. Logs persist as **`TaskCompletion.value`** (same field as Goal). Legacy `incrementalValues` maps are still read.

| Cadence | Example | Grid | Target | Week % | When the target rises |
|---------|---------|------|--------|--------|------------------------|
| **Weekly +** | Meditate *n* minutes | `logged / this week's goal` | Fixed for the whole week, starting at `startValue` | Sum of daily logs / (week goal × 7), capped at 100% | Next **Monday**, only if the previous week had **≥ 4 days** at or above that week's goal. ## Add / Edit Habit window

Opened from the control panel **New habit** control on any Habits tab (or Lists → + Add Habit). Chrome is a Windows 95 window: navy title bar, gray face, one column in this order — name and type, target, completion sources, points, time, priority, done-task wording — labels beside their fields, raised **Add Habit** / **Update Habit** and Cancel. **Gem** starts as a random catalog stone (full folder, 114 PNGs) and can be replaced with another catalog pick or an upload; **Random gem** re-rolls. Changing habit type does not change the jewel. **Priority** is a **Prioritize habit** button with a green star beside it. The star is bright (100%) on the day it was last refreshed and loses 10 points of opacity each calendar day after that (day 3 is 70%, day 10 and after is 0% until the next refresh). The sheet's green uses that same strength. The first press appends `Priority set {date}.`; a later press appends `Priority refreshed {date}.`. Choosing the habit in the morning ritual appends `Selected from day ritual {date}` (week and moon use that ritual's name when a selection there exists). **Permanent priority** holds the star and the sheet highlight at 100% and logs `Permanent priority set {date}.`; turning it off logs `Permanent priority removed {date}.` and the fade continues from the last refresh. Every line is kept, newest first. Dates are the local calendar day, short (`Oct 9`). A habit in today's morning review still shows **MORNING RITUAL** in small tracked capitals and the settings × (default ×5, Habits → Settings, beside the other point rules); the **Morning ritual** checkbox is that membership, and turning it on appends the ritual line. Neglect shows **NEGLECT**, the empty week/month/season count the rule uses, and that count as the compounded ×. **Ignore neglect** sets `priorityMuted`. A fully empty week (or week/month) auto-prioritizes the next period and compounds. Editing also offers **Delete habit**. Type tiles: Yes/No, Goal, Text, Climb. Choosing Climb reveals cadence tiles and start/increment/unit — not a list of named metrics. **Points & bonus** edits `rewardValue` (awarded when newly met) and shows the daily ledger formula (`50 × day ratio`). **Completion sources** is a pipeline (`WeeklyTask.completionPipelines`, flattened to `completionSources`; `lib/habit-completion-pipeline.ts`, `lib/habit-completion-trust.ts`). **Update Habit** writes those rows, the flattened source list, and the row config (the list and its grace, a daily-habit total, the daily floor, Habits stats, and a tagged-task tag) onto the habit. **Add source** asks for a broad type, then that type’s config. The rows that are on sit in trust order; Up or Down moves a row. An optional name is display-only and defaults to the type label. Sources that are off are not shown. Broad types: **By hand** (`manual`), **Tags** (one tag; stored id `taggedTasks`), **Tracking tags** (minutes; stored id `tags`), **Tracking stats** (Activity occupancy and Sleep clock, each turned on inside the row), **Habits stats** (a set of daily, weekly, or monthly habits, then the points added to that row — week grade, perfect output, a day or the set of days, a habit’s completion or the set of habits, and the engines Daily habits floor, Daily habit total, and Daily completion average, each engine still with a plain sentence and a live readout; **Better than last week** is a compare stored on that row), **Lists** (one list; what is counted and what the target is, so the old modes all complete, one complete, one added, and sent this week still load), and **BIM Keywords** (stored id `keywords`). Goal habits can turn on **Cell progress tube**. **Daily habit total** picks one daily habit from a searchable menu inside Habits stats; each week, month, or season cell becomes the sum of that habit on the days so far (`lib/habit-value-sync.ts`). The first source that has something to say wins; an empty source is skipped. A hand-typed cell still wins. Logged numbers and flags stay on the cell — trust only decides whether the habit is met. Occupancy still edits its threshold (default 75; Amount and Complete-at-% stay in sync). Activity paint below that threshold still fills the cell and is an unmet reading; a higher-trust source can override it. A period with no Activity paint is skipped. The daily-floor link still needs a weekly Yes/No. Persist **v25** fills a missing list (By hand first, then whatever was already linked) and does not rewrite completions. **Open item in Lists** (while editing) opens that habit’s standing Lists item (`lib/habit-list-item.ts`, id `habit-item-{habitId}`, list **Habits**) on the same item-detail screen as every other item. The Details main pane is that item’s notes field plus a read-only read of this habit (name, frequency, goal, this period, recent completions). Back restores Home → Habits and reopens this window with the draft. **Habit settings** on the item uses that same return. Double-clicking the Habits list chip opens the Habits list by the item’s list id and does not take the return. **BIM Keywords** edit whole-message Telegram triggers (`WeeklyTask.textTriggers`): keyword, mode (done / quantity / score), optional unit words and score connector. A few spoken words (`for`, `of`, `a`, `the`, …) may sit between the keyword and the number, so `studied for 20 min` counts. **Try a phrase** previews the parser and writes nothing. Quantity **adds** to the running total (40 already logged + 20 = 60); a score replaces; done marks the habit done. The live ingest path adds the same way. Empty habits preview name-matched presets (hemisync, read, exercise, chess); saving stamps them so they stay editable.

**Daily habit total** adds up one daily habit into this weekly, monthly, or season habit. Add **Habits stats**, add the **Daily habit total** point, then choose the daily habit under **Add up this daily habit**. The number in the period cell is that daily habit’s logged amount on the days of this week, month, or season that have already happened, today included. A later day stays out until that day arrives. A day with nothing logged adds nothing, so a blank Tuesday leaves the pages already counted. A Yes/No day with no number counts as 1. Two pages on Monday and two on Tuesday show **4** in the week cell, toward a goal of 30. The same choice is the month total and the season total (`WeeklyTask.habitValueLink`, `lib/habit-value-sync.ts`). Under that point the row says so in a sentence and shows the chosen habit’s name and the sum. **By hand** is the row above Daily habit total until you move them. A number you type into the period cell stays there; the sum is kept beside it (`habitSumValue`) and is what fills the cell when that period has not been typed. While By hand is the first source with something to say, the typed number is what decides the habit.

**Lists** is one pipeline, separate from Tags, Tracking tags, and Daily habit total (`lib/list-sent.ts`, `WeeklyTask.listSentLink`). Add **Lists**, attach a list (the same searchable Win95 menu as the daily-habit picker), and set the routing with two more of those menus — not a native operating-system popup, and not a control labeled only “mode”. **What is counted** is items where a chosen yes/no on the item is true: **Sent** or **Completed**. **Added this period** stays a measure of items added in the period. **What the target is** is the size of this period’s set (items still on the list that have not tripped that yes/no, plus items that tripped it this period — the existing 8/13 sent-this-week total), or the list length, or a fixed **1**. Sent this week is measure **Sent** and target **this period’s set**, which is why 8 sent and 5 unsent is 8/13. The old modes still load as that routing: all complete is Completed and the list length, one complete is Completed and 1, one added is Added this period and 1, sent this week is Sent and this period’s set. A goal habit shows counted/target from those two choices, such as `0 of 5`, plus the names that are still outstanding. **Open list** sits to the right of the list picker. One click opens that list in a popup portaled inside the habit dialog (`DialogContent` `container`). Closing the popup returns to the form with the draft intact. It does not switch to the Lists tab. The popup shows each item’s name with a Sent or Completed control for that source’s measure, Undone only and Show sent (sent rows stay hidden until Show sent), and a Target line such as `0 of 5` when the target is the list length or this period’s set. **Grace** stays on that row (a percent, default 100). The sentence under the field: Grace 100 leaves the raw percent; Grace 80 means a raw 80 counts as 100, and a raw 40 counts as 50 (raw / grace × 100, capped at 100). For the current week — and for a month or season, the same helper on that period’s range — sent is how many items were marked sent during the period, total is those plus the items still on the list and not sent, and the raw percent is sent / total, or 0 when total is 0. Ten to send, send 8, add 3 new unsent is sent 8, total 13, 8/13. A send from a previous week is not in this week’s total; the weekly clear takes it off the list, and unsent items carry over. Reported value = min(100, raw / grace × 100). That reported percent is what the period cell stores (`listSentPercent`, and `value` when the cell was not typed). A hand-typed cell keeps the typed number. The habit’s own goal stays the line. By hand still wins. A missing mode, and a missing measure, is sent-this-week. Missing link or a missing Lists row means off. The stored id for sent-this-week stays `listSent`. Optional `measure` and `target` live on `listSentLink` when the routing is not one of the four old modes; a sent-this-week link can omit them. Persist stays at 26. The weekly habit **respond to all missing texts** (`task-1790202730072`) is attached to the list **texts I need to send** (`1791346611510`) with sent-this-week (measure Sent, target this period’s set) and grace 100. Its goal is 100 because the stored goal was empty. Opening the form and cancelling leaves that link. That binding still loads and still syncs.

**Daily habits floor** is the rule behind a habit like **No 0% completed daily tasks**. Every daily habit’s completion for this period is above 0. The check is binary: the habit is met only when that is true. On a weekly habit the percent shown is that daily habit’s week % column. The row lists each daily habit’s name and that percent. **Allow this many at 0** (`dailyFloorLink.allowAtZero`, optional, default 0) sits on that same link. 0 means every daily habit must be above 0. 2 means two daily habits may be at 0 and the habit is still met. A missing number is 0, so an old habit does not change. Persist stays at 26.

**Daily completion average** is how you make a weekly habit “50% Perfect output for daily tasks”: add a weekly Goal, set the goal to 50, and add **Daily completion average** inside **Habits stats** (`lib/habit-daily-completion-average.ts`). The same point is the monthly habit and the season habit. The period cell becomes the raw mean of each active daily habit's row percent — the same uncurved figure as that habit's week % column. The row says that in a sentence and lists the names and percents that go into the mean. Raw means that uncurved mean, not the Perfect output curve and not the week-grade curve. Yes/No and text are the percent of days met. Goals are the logged amount over goal × days, capped at 100. An empty habit that was active in the span counts as 0. A habit exempt on every day of the span is left out. A week uses that Monday week's seven dates, so a day still ahead counts as not met and the number cannot disagree with the week % column. A month or season uses only the days of that period that have already happened, today included — not a mean of the weekly averages inside the period. The habit's own goal is the line (50 meets a goal of 50). A number typed by hand stays; the average is still stored on `dailyCompletionAverage`. Missing from the pipeline means the source is off. The hint on that Habits stats row is that whole setting. Writes are `withoutUndo`.

**Habits stats points.** Under Completion sources → Habits stats, the first menu is the set: **Daily habits**, **Weekly habits**, or **Monthly habits**. The next menu is a point. Choosing one adds it to that row. The row shows the point’s name. When the point is a set, it also shows a short preview of names and percents, the same idea as the list preview. Daily habits can plug in **Week grade**, **Perfect output**, the day percent for each day of the period, the set of all of those days, the weekly completion percent of each daily habit, the set of all of those habits, and the engines that already have habits: **Daily habits floor**, **Daily habit total**, and **Daily completion average**. List sent and Activity occupancy stay their own source types and are not folded into this menu. Weekly and monthly sets offer that period’s grade, perfect output, each habit’s completion for the period, and the set of all of those habits. Adding an engine point turns that engine on, so the floor, the total, and the average keep the behavior above. Other points are readings on the row. They do not become a new trust id. Persist stays at 26.

**Better than last week** is a choice on that same menu, not a habit created in the vault (`lib/habit-period-compare.ts`). One step stores a rule on the Habits stats pipeline: which points (default this week’s daily-completion average, week grade, and perfect output), compare each one to the previous period, and how many must be strictly higher (default 2 of 3). The user can change the points afterward. A tie is not higher. When at least that many points are higher, the habit is complete for this week. The rule lives on `HabitCompletionPipeline.stats` (`set`, `points`, `comparePrevious`, `mustBeHigher`). It is not written onto the completion cell, and it is not attached to a habit unless that habit is already named “better than last week”.

**Source detail.** A grid cell whose pipeline includes **By hand** stays an editor. Double-click still edits the value, and the detail does not open. A cell whose pipeline does not include By hand is not an editor. Double-clicking it opens a read-only detail of that square (`habit-source-detail.tsx`): the habit name, the period (that day, week, or month), each source that was asked, the numbers it pulled, and the result. Closing it writes nothing. When the row compares to the previous period, the detail also shows each pair, which side won, and the count (2 of 3).
