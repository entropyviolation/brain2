# `components/Home/Habits/` — Habit Tracker

The Home **Habits** sub-tab — the house’s **favorite surface** and most developed UI. Other rooms look here for the **Habits Tab Control Panel**, analog furniture, **Willpower gems**, CRT phosphor, and designrefs skeuomorph ([`docs/DESIGN_STYLE.md` — Look at Habits](../../../docs/DESIGN_STYLE.md#look-at-habits--how-to-extend)). Supports five measurement types (boolean, goal, text, climb) at **daily**, **weekly**, and **monthly** frequencies. TIME/COUNT are legacy aliases for GOAL.

Climb (incremental) habits are **not** a per-key spreadsheet. They log one number per day, like a goal, with a derived target. Rules live in **`lib/incremental-habits.ts`**.

## Data

Single source of truth: **`lib/habits-store.ts`** (Zustand + persist, key `cogs-habits-store`, **version 20**). Persist **v20** stores the exemption wand. `migrateHabitsState` spreads any recent blob and only fills missing keys (sort, LED tint, day view, loading bar, **Small LEDs**, gems, tube colors, **control panel width** pinned compact, Willpower gems physics). Persist **v19** adds **`contentRev`**: every title, detail, and completion write stamps the vault, and a late rehydrate or an older same-sized snapshot cannot roll those edits back. Persist **v18** resets leftover `willpowerPhysics` knobs to the calm default whirl. A present `percentLedTint` / `gradeTubeColor` / `outputGradeTubeColor` is never replaced with the Home overview defaults (`#7e14ff` / `#508b51` / `#25366a`). Custom hues with `appearanceRev` 0 are stamped to 1 so a seed hydrate cannot roll them back. It never replaces `tasks` or completions with `[]`. Electron `userData` is pinned to `~/Library/Application Support/cogs` so a package rename cannot boot an empty profile. Daily Habits waits on `usePersistHydrated` so a hub fetch cannot flash seed rows (or “No habits yet”) over the vault; Electron returns a rich local snapshot immediately instead of parsing the 2MB persist hub first. A richer hub vault still overlays those local color keys (and `cogs-theme-store` `pcbMode` / `chromeFace` / `colors`) so an older hub JSON cannot reset them. **`appearanceRev`** bumps on each LED / tube hue pick; a late hub rehydrate keeps the live pick. `choosePersistSnapshot` re-reads disk so a color change during the hub wait is not merged from a stale getItem snapshot. Persist **writes** stamp `cogs-habit-led-tint` from the new blob; they do **not** re-apply a stale pin onto that blob (that was resetting Percent LED tint to a previous purple on refresh). The LED swatch stays disabled until the habits vault has hydrated so a native color input cannot POST a seed tint before the snapshot lands.

Each `WeeklyTask` may be **`priorityPinned`** (until unpinned) and/or **`priorityMuted`** (drops auto-priority). A fully empty prior week (daily) / week / month auto-prioritizes the next period and compounds. **`gem`** is a catalog path or uploaded data URL for that row’s edit jewel. New habits get a **random** stone from the full `public/gems-removebackground/` catalog (114 PNGs). Existing habits with no stored gem get one on persist **v13** (lazy stamp). Type / category no longer pick the row jewel. A user pick or upload still wins and is not re-rolled.

Persist **v20** adds the exemption wand (`exemptionWand`, `habitExemptions`). Periods that end before the habit existed are exempt with no stored flag (`createdAt`, or the `task-{unix ms}` id when older rows never received that field). A wand click writes an override and clears it when the choice matches that automatic rule again. Persist **v19** stamps `contentRev` on habit titles, details, completions, and exemption overrides so a stale snapshot cannot replace them. A hollow live vault (empty completions, or seed `task-*` rows) with a newer stamp still **overlays disk completions** and heals seed tasks so Week grade / Perfect output do not go blank. Gem stamping after rehydrate does **not** bump `contentRev`. **`hideCompletedToday`** persists with the other control-panel rockers (no version bump). Persist **v18** resets `willpowerPhysics` to the calm default whirl. Persist **v17** pins `habitsControlPanelWidth` back to 196px (seam resize retired). Persist **v16** adds `habitsControlPanelWidth`, `willpowerPhysicsHud`, and `willpowerPhysics`. Persist **v15** adds `habitSmallLeds` (default on). Willpower gems satellites are **derived** — **one copy per daily completion** on the visible week (`lib/willpower-stones.ts`, id `habitId:YYYY-MM-DD`) — no extra collected-id persist, so reload keeps the same stones. Persist **v14** adds `gradeTubeColor` / `outputGradeTubeColor`. Persist **v13** stamps missing `WeeklyTask.gem` values. Persist **v12** adds `habitDayView` and `percentLoadingBar` (default on). Persist **v11** adds `percentLedTint`. Persist **v10** adds `habitSortMode` (old `sortHabitsByPriorityFlag` true → `priority`, false → `default`). Persist **v9** adds `habitGems`. Persist **v8** adds `willpowerImage`. Persist **v7** adds those flags and toggles. Persist **v6** adds the Good-day settings. Persist **v5** adds `outputGradeTolerance`. Persist **v4** adds `gradeTolerance`. Persist v3 migrates old multi-metric climb maps (`currentValues` / `weeklyIncrement`) into one habit per metric and copies logs onto `TaskCompletion.value`. Legacy `weekly-habits-*` localStorage keys are imported once on first load. New habits stamp `WeeklyTask.createdAt`. Version bumps call `migrateHabitsState` so older JSON (v9/v10/v13) still hydrates tasks.

Completing a habit awards **50 points × that day’s completion ratio** (partial goals/climbs count) via `lib/habit-points.ts` / `points-store.upsertPoints`, and writes a `loggedAction` Done row (`lib/habit-done-log.ts`, id `habit-done-{habitId}-{YYYY-MM-DD}`) so it appears in To-Do **Done** (today / this week / this month) and in Analytics task counts. Unchecking removes that row and zeros that habit’s points for the day. **Cmd/Ctrl-Z** reverses a cell you just marked (`lib/action-history.ts`). Each elapsed day can also earn the **accomplishment bonus** if that day’s score (raw, or the 50% priority blend when `goodDaysUsePriority` is on) meets `accomplishmentThreshold` (defaults: ≥80% → +50), **+100** if either Week grade or Perfect output is 75%+ after its curve (and optional priority blend), or **+300** if both grades are.

The same store is used by **`Lists/daily-habits-list.tsx`** — changes in Home or Lists stay in sync.

## Exemption wand

A period that does not apply is **exempt**: it leaves the requirement. It is not a completion.

| Rule | What it does |
|------|----------------|
| Before the habit existed | A day, week, or month that **ends** before the habit existed is exempt on its own. The day is `createdAt` when it was stored; otherwise the `task-{unix ms}` id from add time. The creation day, the week that contains it, and the month that contains it stay required. A seed id such as `task-1` is not a date, so those rows have no automatic waiver. |
| All-nighter block | On a daily habit, **Lift when a log says** (`logExemptions`). An all-nighter is the morning date. `evening-before` lifts the day that led into that night (bedtime). `morning-of` lifts that morning (wake, dream). `undefined` uses the name preset; `[]` means the preset was cleared. Weekly and monthly ignore it. A wand “require” beats the block. The chart uses the same grey hatch, titled for that night or that morning. Morning Review lists the blocks under the checkbox. |
| Wand | Control-panel wand stays metal. Pressed, it is crossed out and every cell becomes a yes/no lamp for “waived.” On = grey, unavailable. Off = the ordinary dark lamp (required). Clicking back to the automatic rule deletes the override. The crossed wand leaves the mode. |
| On the chart | With the wand off, an exempt cell is a grey hatch (`.habit-exempt`, cell `.is-exempt`). It is not a lit completion and not an empty miss. The heatmap square uses the same grey (`.is-exempt`). |
| Day % | Denominator is the habits still required that day. Three habits, one waived → divide by 2. |
| Row % | Denominator is the periods still required. One waived day in the week → divide by 6, and that day is not a hit. A goal’s target shrinks the same way. A window where nothing is required shows **—**. |
| Grades | A day or period where every habit is exempt is left out of the average (shown as “exempt” on the milled grade sheet). A habit with no required periods in the window is left out of Perfect output. |
| Hide completed | Also hides exempt rows for the focused day / week / month. |
| Still to do | Plan rail, Home day counts, Lists done/total, morning-review habit picks, and friend suggestions treat exempt like unavailable: not remaining, not done. |
| Points and gems | An exempt day pays 0 habit points and does not drop a Willpower gem. Un-waiving restores both from the completion that is still stored. |

## Connections

Daily yes/no habits can check themselves from a log. The blocks live on the habit form (**Connections**), so another habit can be wired the same way. A hand tick still counts.

| Block | What it watches |
|-------|-----------------|
| Sleep clock | Bedtime on a day is the evening that leads into the next morning’s night. Wake is that morning. The habit is met when the logged end is at or before the threshold. Name preset: bedtime (11pm if the name has no hour), or wake plus “before” (9am if the name has no hour). |
| To-do list | How many items on a named list, inside Next Actions, were completed that day. The preset is **complete 1 to-do list item** → 1 done item on the list named “to do”. That block is the template: change the count or the list name to make the same connection on another habit. |

`undefined` uses the name preset. `null` means it was turned off. `sleepCompleted` and `listCompleted` mark the auto check the way tracked time uses `trackedCompleted`.

## Time estimate

A habit records an *amount* ("4 pages"), but it always consumed time, and that
time is what makes its Done row worth anything to the review or to Analytics. Add/Edit
Habit → **Time estimate** (`WeeklyTask.timeEstimate`) supplies the missing scale:

| Control | Meaning |
|---------|---------|
| Minutes per *unit* | Scales with what was logged. 10 min per page × 4 pages written = 40m — the amount **logged**, not the goal. Goal and Climb habits only. |
| Minutes per completion | A flat length. The only option for Yes/No and Text habits; on a Goal habit it is the fallback when no rate applies. |
| This length is exact, not a guess | `precision: "definite"`. The derived duration is recorded as fact instead of being flagged for confirmation. |

Habits already measured in time (unit `minutes` / `hours`) need no estimate — the
logged value *is* the duration, and it is recorded unflagged. Painted Tracking time
outranks a rate: minutes on the habit's linked tags are observed, and a rate is
only used to top up a hand-logged remainder.

Meeting the goal then writes a Done row carrying the duration **and** a clock
window (`lib/completion-window.ts`): the painted Tracking run when there is one,
otherwise "finished just now" for today, otherwise — for a day already over —
half an hour before that night's bedtime, taken from the sleep log, from sleep
painted on the grid, or from the median bedtime of the last month, and only then
the fixed day anchor (default 9:00 PM). Anything assumed is flagged and shows as
**est.** in Home → To Do → Done, where it can be confirmed or corrected.

## Auto-fill from Tracking

A daily **Goal** or **Yes/No** habit can carry a `trackingLink` (`lib/types.ts`) that pulls time straight out of Home → **Tracking**. Tag a pen there (e.g. "Do dishes" → *Cleaning*), link the tag here, and every minute painted with any pen carrying it lands on the habit for that day. Weekly and monthly Goal / Yes/No habits use the same control: tagged minutes are **summed across the week or calendar month** and written to `weeklyHabitData` / `monthlyHabitData`.

Set it in Add/Edit Habit → **Auto-fill from Tracking**:

| Control | Meaning |
|---------|---------|
| Tag chips | Any pen carrying one of the selected tags counts. Slots are unioned across scopes, so a minute tagged in two scopes counts once. |
| Count tracked time as | `minutes` (default) or `hours` (2 decimals), matched to the habit's unit. |
| Combine with manual entries | **Add** (default) tops up what you typed, **Higher of the two**, or **Tracking only**. |
| Minutes needed to check it off | Yes/No habits only — threshold before the box ticks itself. Blank = any tracked time. |
| Auto-fill is on | Suspends the link without losing the tag selection. |

Below the chips the form reports how many pens currently feed the habit, so an unused tag is obvious before saving.

**How the value is stored.** The completion keeps the two halves apart — `manualValue` (typed) and `trackedValue` (from the grid) — and `value` stays their combination, so grade math, points, week % and the Done log need no special case. That split makes the sync idempotent: repainting recomputes instead of accumulating, erasing time withdraws it, and typing a number into a linked cell is read as the new **total** (the manual half is back-solved). Completions written before a link existed are treated as fully manual, so linking never erases logged history.

Auto-filled cells are marked in the grid with a clock glyph and a blue border; hovering shows the split (`60 minutes from Tracking + 10 logged by hand`). Yes/No boxes ticked by the tracker get a blue ring, and only those are un-ticked when the time goes away — a hand-ticked day stays ticked.

An Operation can carry the same tags (Settings → Tracking & habits). Time spent **Working on this now** is painted onto the Activity grid with those tags, so this auto-fill runs without a second wiring. See `components/Operations/README.md`.

Climb and Text habits are out of scope (`supportsTrackingLink`); their targets are derived rather than accumulated. Modules: `lib/tracked-time.ts` → `lib/habit-tracking.ts` → `lib/habit-tracking-sync.ts`.
