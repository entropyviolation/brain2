# `lib/` — Data model, state stores, and pure helpers

This folder is the **nervous system** of a living perfect second brain: one
Item graph (capture once; use in as many rooms as possible), one persist path,
one vocabulary that every future installed room inherits. **Data** reads
this mass; it does not invent a second ontology.
Everything that is **not** React UI: the TypeScript data model, Zustand stores
(persisted to localStorage — the offline-first source of truth). The
sync that exists is the manual phone hub (`lib/mobile-sync.ts`). MongoDB
Atlas, `@brain2/core`, and Expo are speculation, not the storage plan
(`docs/SPEC_MAPPING.md` §3). Also in this folder: pure
calculation, date, and sync utilities.

> React Native app are not scheduled. `DataSource` files are unwired
> scaffolding. The sync that exists is the manual phone hub
> ([`docs/SPEC_MAPPING.md`](../docs/SPEC_MAPPING.md) §3).

## Zustand stores

localStorage keys are **`brain2-*`**. Historical **`cogs-*`** keys are a lossless
alias (`storage-keys.ts`): copy onto `brain2-*` when missing; small pins still
dual-write; large vaults write `brain2-*` only so origin quota is not doubled.
Oversized duplicate `cogs-*` twins are dropped on boot once `brain2-*` exists.
Settings **Data profile** can switch **Live** (default)
vs **Demo**; Demo physical keys are **`brain2-demo-*` only** (`data-profile.ts`,
`demo-vault.ts`) and never dual-write Live. Bytes — attachments, pasted pictures,
Docs HTML — belong in IndexedDB, not in a store's JSON: the origin holds ~5MB for
*all* keys together, so one picture in a Lists attribute can stop Tracking from
saving. IndexedDB (`cogs-attachments`, `cogs-docs` live;
`brain2-demo-docs` / `brain2-demo-attachments` on Demo), CSS
(`.cogs-color-swatch`), and Electron userData folder `cogs` are not persist keys
and stay. The product name is **Brain2** / **BRAIN2**.

## Autogenerated values are always flagged

The app derives a lot of data the user never typed — how long a habit took, when
in the day it happened. None of it is presented as observed fact. Anything derived
carries a `FieldEstimate` on the record (`Task.estimates`, `lib/estimated-values.ts`)
naming the field, how it was produced, and the sentence explaining it. That buys
two things at once: records get filled in automatically, and the review can hand
the user a short list of "is this right?" instead of a wall of silent guesses.
A separate glance, `usualDurationMinutes`, medians observed sessions of the same
title or named type and paints **usually ~N** — it is never persisted as
`estimatedDuration` or a `FieldEstimate`.

Wave 13 (GS-1) grows `FieldEstimate` with an order — observed, recorded,
derived, inferred — and uses this same mark everywhere a number was computed
or guessed. Do not add a second provenance type.
[`docs/ScienceandSanityBrain2.md`](../docs/ScienceandSanityBrain2.md).

The rules that hold this together:

- **Observed beats assumed.** Painted Tracking minutes and a habit already measured
  in minutes/hours are recorded *unflagged*; a per-unit rate or a flat length is
  flagged. `precision: "definite"` on a habit's time estimate opts out.
- **Confirmation is sticky.** `canRegenerate` blocks any later sync from
  overwriting a value the user confirmed, which is what makes it safe to re-derive
  on every habit edit.
- **Never chase the clock.** A finish time is stamped once, when the goal is first
  met. Logging more later lifts the duration and slides the *start*, so the record
  does not rewrite itself while the user types.
